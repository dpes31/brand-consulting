[VISUAL INTENT BRIEF — GATE 2A TEST]
일반 분석과 COMPETITOR_REGISTRY를 먼저 작성한 뒤, 응답 마지막에 VISUAL_INTENT_BRIEF를 작성하십시오. HTML/CSS/SVG는 작성하지 마십시오.

출력 순서: 일반 분석 → COMPETITOR_REGISTRY → VISUAL_INTENT_BRIEF

허용 evidenceType:
- priority-ranking
- causal-relationship
- quantitative-comparison
- competitive-space
- evidence-gap

허용 Recipe:
- rank-scorecard
- competitor-threat-system
- feature-matrix
- positioning-map
- evidence-gap

pilot-supported:
- competitor-threat-system
- feature-matrix

필수 Brief:
- Threat Ranking 정확히 1개: priority-ranking → rank-scorecard
- COMPETITOR_REGISTRY selected 경쟁사마다 독립 Deep Dive 정확히 1개: causal-relationship → competitor-threat-system
- Product Matrix 정확히 1개: competitive-space → feature-matrix
- 근거 있는 공통 축 2개가 있을 때만 Positioning Map 최대 1개: competitive-space → positioning-map
- 해당 역할의 근거가 부족할 때만 evidence-gap → evidence-gap

Deep Dive 규칙:
- 흐름: Evidence → Core Desire → Appeal → Threat Mechanism → Attack Point
- 경쟁사 여러 개를 하나의 Deep Dive Brief로 합치지 마십시오.
- 아래 Deep Dive 예시 객체를 selected 경쟁사 수만큼 복제하십시오.
- 각 Deep Dive의 entities에는 COMPETITOR_REGISTRY의 해당 selected 경쟁사명 정확히 1개만 넣으십시오.
- 경쟁사명은 Registry와 철자·띄어쓰기·기호까지 정확히 일치해야 합니다.

Product Matrix와 Positioning Map 규칙:
- Product Matrix는 조사 브랜드와 selected 경쟁사만 사용하십시오.
- 모든 브랜드에 동일하게 적용되는 공통 비교축만 사용하십시오.
- Positioning Map은 근거 있는 두 축이 없으면 생성하지 마십시오.
- 비교축·점수·수치를 임의 생성하지 마십시오.

Metric 계약:
- metrics를 하나라도 사용하면 각 객체에 metricId, label, value, unit, period, denominator, sourceLabel, verificationStatus를 모두 작성하십시오.
- metricId는 영문·숫자·하이픈으로 만든 고유 ID입니다.
- value는 숫자입니다.
- denominator는 비교 기준이 없으면 null입니다.
- sourceLabel에는 URL 대신 출처명·자료명·연도를 적으십시오.
- verificationStatus 허용값은 verified, partially-verified, unverified뿐입니다.
- 공식 통계·공시·정부기관 자료에서 정확히 확인된 수치: verified
- 회사가 직접 발표했으나 독립 검증이 제한된 수치: partially-verified
- 공개 근거를 종합한 분석 점수: partially-verified
- 단일 미확인 주장 또는 교차 검증되지 않은 추정치: unverified
- 수치가 필요하지 않으면 metrics는 []로 두십시오. 불완전한 Metric 객체를 넣지 마십시오.

Primary 1개와 Fallback 최대 1개만 선택하고 requiredInputs, availableInputs, missingInputs를 분리하십시오. 외부 템플릿 이름이나 번호를 recipeId로 사용하지 마십시오.
